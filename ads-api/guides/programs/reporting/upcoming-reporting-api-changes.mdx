---
title: "Upcoming Changes to the Reporting API"
---

We’re making several changes to the Reddit Ads Reporting API to improve its reliability, performance, and consistency at scale.

These changes align the query patterns supported by the Reporting API more closely with those supported in Ads Manager. We’re also documenting replacements for deprecated and legacy metrics and updating how late-arriving conversion data is reflected in reports.

Some changes may require updates to your Reporting API integration. Review the changes, required actions, and timeline below.

## What is changing

### Hourly reports will be limited to a 7-day date range

Reporting requests that use the `HOUR` breakdown will support a maximum date range of 7 days per request. The requested range can be any continuous 7-day period; it doesn't have to be the most recent week.

**Action required:** If your integration requests hourly data for periods longer than 7 days, divide the date range into multiple requests of 7 days or less.

### Certain breakdown combinations will no longer be supported

A reporting request can include no more than 1 of the following breakdowns:

-   `KEYWORD`
-   `COMMUNITY` or the legacy `SUBREDDIT` value
-   `INTEREST`
-   `LANGUAGE`

In addition, those breakdowns can't be combined with any of the following breakdowns in the same request:

-   `DMA` or its `METRO` alias
-   `REGION`
-   `GALLERY_ITEM_ID` or its `CAROUSEL_CARD` alias
-   `OS_TYPE`
-   `COUNTRY`

**Action required:** Review your reporting requests for these combinations. If your integration requires multiple affected breakdowns, submit separate requests and combine the results in your system as appropriate.

#### Custom conversion reporting

Use the name-keyed `conversion_custom_events` request structure. `conversion_custom_events` is a top-level request property, not an entry in the `fields` array. For each custom event, add an object with the exact, case-sensitive event `name` and a `metrics` array. Each entry in `metrics` must include one of the supported `metric_type` values below; include `action_sources` where applicable.

| Supported `metric_type` |
| --- |
| `VIEWS` |
| `CLICKS` |
| `ECPA` |
| `TOTAL_VALUE` |
| `TOTAL_ITEMS` |
| `AVG_VALUE` |
| `ROAS` |

See [Retrieve a Custom Conversion Event Report](/ads-api/guides/programs/reporting/get-custom-event-report) for the request structure and migration example.

### Late-arriving conversion data will be reflected during daily refreshes

Conversion data received for the current hour will continue to be processed in the current hourly batch. Late-arriving conversion data associated with a prior hour or day will be reflected when historical data is corrected during the daily refresh.

This change applies to reporting in both the API and Ads Manager. It doesn't require a request-format change, but previously retrieved historical totals may be updated after the daily refresh.

**Action recommended:** If your integration reconciles or finalizes conversion totals shortly after events occur, account for the possibility that historical totals may be corrected during a subsequent daily refresh.

## Effective date

These changes take effect on **December 8, 2026**. Review your integration, determine whether updates are required, and complete and deploy any necessary changes before this date.

Beginning on the effective date, requests that don't meet the new hourly date-range or breakdown-combination requirements will be rejected. Test and deploy your updates in advance to avoid reporting interruptions.

For questions or support related to these changes, contact the [Ads API Support Team](https://support.reddithelp.com/hc/en-us/requests/new?ticket_form_id=50388520825236).
